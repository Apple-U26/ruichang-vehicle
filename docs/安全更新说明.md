# 安全与数据一致性更新

本次更新保持现有数据库结构、登录凭证和手机端页面兼容。

## 行为调整

- 删除车辆或焊机后，其余资产的数据库 ID 和资产编码保持不变；列表可能出现序号空缺。
- 同一张报销单不能重复关联同一笔费用。出车、收车、报销创建与审核的关键操作增加数据库行锁。
- 报销展示编号使用数据库分配的唯一 ID，保持 `BX-月份-编号` 格式，允许编号跳号，并兼容历史编号冲突。
- 项目负责人、车辆负责人的详情、编辑、报销审批和台账导出按负责范围校验。已绑定的项目负责人账号 ID 优先于显示姓名，姓名模糊匹配不再用于授权。
- 驾驶员不能导出台账，财务不能登记出收车。旧版 Excel 导入会修改跨项目数据，因此该入口限制为管理员。
- 应用启动时不再按相近姓名自动修改项目负责人；字段类型已经符合要求时跳过重复的 ALTER TABLE。
- `/api/health` 增加 `release` 字段，可通过服务环境变量 `APP_RELEASE` 标记部署版本。

## 验证

在后端开发环境安装 `requirements-dev.txt` 后运行：

```bash
cd backend
python -m unittest discover -s tests -v
```

测试强制使用隔离的内存 SQLite 数据库，覆盖登录、连续删除、绑定关系、同单与跨单重复费用、历史编号冲突、项目权限、批量审批回滚、导出范围和正常驾驶员出收车等场景。

生产发布前还应在独立 MySQL 测试库验证真实外键、事务和并发行为；不能把有写操作的回归测试指向生产数据库。

## 发布与回退

1. 备份数据库、附件、代码、Nginx 配置及 systemd 服务配置，并记录校验值。
2. 使用独立目录与内部端口启动待发布版本，复用原有依赖；先验证健康检查和各角色只读访问。
3. Nginx 配置通过语法检查后 reload，临时转发到已验证版本，保持原服务可用。
4. 更新主服务代码并重启主服务；确认功能正常后，把 Nginx 流量切回主服务。
5. 若任何检查失败，恢复备份配置并回到原服务。回退代码时不应覆盖发布后的正常业务数据。

本批未更改原有附件公开访问方式及登录会话机制；附件资源授权和长期令牌下载方式应在下一批配合前端一起调整。
